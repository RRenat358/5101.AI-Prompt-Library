[BEHAVIOR: Role — форм-фактор]

При создании, редактировании и анализе ролевых инструкций применяй обязательный форм-фактор.

------------------------------
**ОБЯЗАТЕЛЬНЫЙ ШАБЛОН:**

```
[ЯДРО РОЛИ]
Ты — [суть роли].
[Опционально: строка Стойки — только если переопределяем дефолт]

[КОМПЕТЕНЦИИ РОЛИ]
- [Цель / миссия / основной вектор роли]
- [Компетенция 1]
- [Компетенция 2]
...
```

Последним пунктом всегда ставь маркер открытости:
«Любые смежные задачи, соответствующие роли (не ограничивайся перечисленным).» или аналогичный.

Дополнительные блоки ([ТОН И СТИЛЬ], [ОГРАНИЧЕНИЯ] и т.п.) --
добавляй, только если они не дублируют существующие Behavior-модули или другие;
если блок разрастается — выноси в отдельный блок-сущность.
Оформляй эти блоки так же — заголовком в квадратных скобках и маркированным списком.

------------------------------
**ПРАВИЛА:**
- Ядро роли — одна фраза «Ты — ...». Сохраняй его максимально чистым.
- Миссия, цель или специализация описываются первым пунктом блока компетенций (или любого другого блока, идущего сразу
  после блока [ЯДРО РОЛИ]) — этого достаточно в подавляющем большинстве случаев.
  Добавлять миссию в ядро допустимо только в крайне редких ситуациях, когда без неё идентичность роли неразличима или
  принципиально неполна (например, две роли с одинаковым названием, но разной специализацией).
- Заголовок для компетенций: [КОМПЕТЕНЦИИ РОЛИ].
  Допустимые альтернативы: [КЛЮЧЕВЫЕ КОМПЕТЕНЦИИ], [ЗНАНИЯ И НАВЫКИ], [КЛЮЧЕВЫЕ СФЕРЫ]. Выбери один и придерживайся его.
- В блоке компетенций указывай по пунктам домены/области — этого достаточно для любой роли.
- Перед списком в компетенциях можно поставить lead-in для живости и побуждения к действию,
  например «Знаешь и активно применяешь:». Это стилистический выбор, применяй по ситуации.
- Домен в компетенциях можно записывать с глаголом, когда это помогает: намеренно сузить область или естественно подчеркнуть действие.
  Подбирай глагол по широте домена: узкое действие — конкретный глагол (пишешь, диагностируешь),
  широкий домен — широкий глагол (владеешь, решаешь задачи).
  Сведение широкого домена к одному узкому действию сужает роль. Идентичность задаётся только в ядре роли.
- Каждый пункт добавляет роли смысл: описывай то, что отличает роль от дефолтного ассистента.
- **База vs углубление.** В компетенциях — база роли: маркеры областей, 1 строка,
  без техник. Техники, чек-листы, подводные камни — в Skill, не в Role.
  Тест: убери — роль откажется или сменит рамку = база. Роль ответит, но
  менее глубоко = Skill.
- Оптимальное количество компетенций — 3–7. При большем числе группируй близкие.
- Согласовывай с другими активными блоками: дублирующие правила объединяй, конфликты приоритетов разрешай явно.

------------------------------
**ЧЕКЛИСТ ПРОВЕРКИ:**
- [ ] Роль открывается строкой «Ты — ...» без лишнего текста, кроме опциональной Стойки (если она нужна).
- [ ] Первый пункт первого блока после ядра задаёт миссию, цель или специализацию роли
      (в исключительных случаях — допустимо в ядре).
- [ ] Присутствует блок с компетенциями ([КОМПЕТЕНЦИИ РОЛИ] или согласованный аналог).
- [ ] В пунктах нет вложенных «Ты — ...».
- [ ] Если домен записан с глаголом, глагол соответствует широте домена
      (узкое действие — конкретный глагол, широкий домен — широкий глагол).
- [ ] Компетенции — база (маркеры), без техник и чек-листов (это Skill).
- [ ] Явная Стойка — только если переопределяет дефолт.
- [ ] Нет дублирования поведения, ожидаемого от роли по умолчанию.
- [ ] Последний пункт компетенций — маркер открытости.

[BEHAVIOR: Action — форм-фактор]

При создании, редактировании и анализе Action применяй обязательный
форм-фактор.

------------------------------
**ОБЯЗАТЕЛЬНЫЙ ШАБЛОН:**

```
[ACTION: <название>]
[Опционально: Мыслишь как <роль> — только если нужно переопределить дефолт]
Задача: <что сделать, глаголом>

[Алгоритм / Структура / Чек-лист]
```

------------------------------
**ПРАВИЛА:**
- **Операция первична.** Action отвечает на «что сделать», а не «кто ты».
  Роль в Action — угол выполнения, не суть.
- **Роль опциональна.** Пиши её, только если задача без неё неоднозначна,
  нужен специфический угол или фиксация. В остальном дефолт LLM подтянет
  подходящую роль из контекста операции.
- **Встроенные элементы допустимы.** Behavior (тон), Skill (техники),
  Format (структура) могут быть внутри Action. Сохраняй фокус на операции:
  Action — про действие, не про всё сразу.
- **Тест на «Ты — …».** Если в Action есть «Ты — …» — убери его мысленно:
  задача осталась понятной? Да → это Action, роль была углом. Нет → это Role,
  не Action.
- **Имя файла** — `<имя>.ACTION.txt` (или без суффикса в папке `actions/`).

------------------------------
**ЧЕКЛИСТ ПРОВЕРКИ:**
- [ ] Операция сформулирована глаголом: создай, проанализируй, перепиши,
      сегментируй?
- [ ] Роль опциональна и не перегружает задачу?
- [ ] Без «Ты — …» задача остаётся понятной?
- [ ] Встроенные элементы (если есть) не подменяют операцию?
- [ ] Имя файла соответствует правилам?

[BEHAVIOR: Behavior — форм-фактор]

При создании, редактировании и анализе Behavior применяй обязательный
форм-фактор.

------------------------------
**ОБЯЗАТЕЛЬНЫЙ ШАБЛОН:**

```
[BEHAVIOR: <название>]
Мыслишь как <диспозиция или роль>.
[Опционально: одна строка уточнения диспозиции]

[ПРИНЦИПЫ]
- <принцип поведения>
- <принцип поведения>
```

------------------------------
**ПРАВИЛА:**
- **Маркер Behavior — «Мыслишь как …».** Если нужна идентичность «Ты — …» —
  это Role, не Behavior.
- **Behavior — practice.** Предписывает, как действовать: тон, манеру,
  аналитическую рамку. Не содержит техник и чек-листов — это Skill.
- **Два уровня силы.** Тон (Коллега) — меняет манеру. Диспозиция (Критик) —
  задаёт рамку, неявная идентичность появляется. Сильный Behavior без Role
  может подменить идентичность — подключай к Role.
- **В Composite — не меняет стойку Role.** Если Behavior меняет стойку —
  это вторая стойка, не Behavior. Критик на Психологе — Behavior.
  Безопасник на Сисадмине — вторая стойка, не Behavior.
- **Имя файла** — `<имя>.BEHAVIOR.txt` (или без суффикса в папке
  `behaviors/`).

------------------------------
**ЧЕКЛИСТ ПРОВЕРКИ:**
- [ ] Начинается с «Мыслишь как …» или списка предписаний, без «Ты — …»?
- [ ] Это practice (как действовать), не knowledge (что знать)?
- [ ] В Composite не меняет стойку Role?
- [ ] Если сильный Behavior — подключён к Role, не работает один?
- [ ] Имя файла соответствует правилам?

[BEHAVIOR: Skill — форм-фактор]

При создании, редактировании и анализе Skill применяй обязательный
форм-фактор.

------------------------------
**ОБЯЗАТЕЛЬНЫЙ ШАБЛОН:**

```
[SKILL: <название>]
Область: <что покрывает>

- <техника / подход>
- <подводный камень / антипаттерн>
- <чек-лист: что проверить>
```

------------------------------
**ПРАВИЛА:**
- **Маркер Skill — `[SKILL: <название>]` + «Область:».** Содержит техники,
  чек-листы, подводные камни. Предписания поведения («всегда делай X») —
  это Behavior, не Skill.
- **Skill — knowledge.** Углубляет то, что модель уже делает. Не задаёт
  тон и не меняет диспозицию.
- **Stance-neutral.** Убери Skill мысленно: модель всё равно возьмётся
  за задачу, но ответ будет менее глубоким. Если без файла модель
  перестаёт браться или меняет стойку — это Behavior или Role.
- **Имя файла** — `<имя>.SKILL.txt` (или без суффикса в папке `skills/`).

------------------------------
**ЧЕКЛИСТ ПРОВЕРКИ:**
- [ ] Область определена?
- [ ] Есть техники и подводные камни, не только общие слова?
- [ ] Stance-neutral? (убери — модель берётся за задачу)
- [ ] Нет предписаний поведения («всегда делай X»)?
- [ ] Имя файла соответствует правилам?

[BEHAVIOR: Format — форм-фактор]

При создании, редактировании и анализе Format применяй обязательный
форм-фактор.

------------------------------
**ОБЯЗАТЕЛЬНЫЙ ШАБЛОН:**

```
[FORMAT: <название>]
Правило: <что и как оформить>

[Пример — опционально, абстрактный]
```

------------------------------
**ПРАВИЛА:**
- **Format — presentation, не content.** Задаёт оформление вывода, не
  содержание и не поведение. Не меняет смысл ответа — только его вид.
- **Content-neutral.** Убери Format мысленно: содержание то же, оформление
  другое. Если меняется смысл — это Behavior или Skill.
- **Пример — абстрактный.** Конкретный пример (с реальными словами, командами,
  форматами) может «притянуть» модель к этому примеру. Если пример нужен —
  используй плейсхолдеры: `<что>`, `<куда>`, `<как>`.
- **Имя файла** — `<имя>.FORMAT.txt` (или без суффикса в папке `formats/`).

------------------------------
**ПРИМЕР (абстрактный):**

```
[FORMAT: Пример]
Правило: добавляй <метку> в <начало или конец> каждого <блока или сообщения>.

Пример:
<метка> <содержимое>
```
