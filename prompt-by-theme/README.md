# Тематические витрины (prompt-by-theme)

Артефакты одной темы в одном каталоге: роли, скиллы, actions, behaviors —
всё, что нужно для работы с темой, лежит рядом.

Витрина — это не сущность и не вторая иерархия. Это **полка**: удобный
обзор для темы, которая набрала достаточно артефактов.


============================================================
## Зачем

Работая с темой, хочется видеть всё нужное в одном месте, а не собирать
по сущностям: роль из `prompts/roles/`, скилл из `prompts/skills/`, action
из `prompts/actions/`. Витрина решает это: зашёл в `psychology/` — видишь
всю тему.

Публичные библиотеки промтов обычно организованы как раз по темам и только
по темам. Здесь тема — вторичный признак: основная структура — по типам
сущностей, а витрина — дополнение для удобства.


============================================================
## Как устроено

```text
prompt-by-theme/
  education/
  it/
  it-llm/
  psychology/
  spirituality/
  writing/
```

**Правило создания темы.** Тема создаётся, когда выполнены оба условия:

1. **≥2 артефакта** (Action, Behavior, Format, Role, Skill, Snippets)
   тематически связаны и используются вместе.
2. **Связь устойчива** — файлы образуют рабочий набор, а не случайное
   соседство.

**Что не считается артефактом темы:**
- **Sidecar-документация** (`<мишень>.GUIDE.txt`, `<мишень>.README.md`).
  `Роль.txt` + `Роль.GUIDE.txt` = 1 артефакт, темы нет.
- **Композиты** — они живут в `prompt-composites/` независимо от темы.

**Общие файлы не дублируются.** Если Skill используется и вне темы — он
остаётся в `prompts/skills/`, в теме не повторяется.

**Внутри темы:**
- файлы лежат плоско, если одного типа < 3;
- подпапка сущности (`actions/`, `behaviors/`, `formats/`, `roles/`,
  `skills/`) создаётся, если файлов этого типа ≥ 3;
- в плоском каталоге темы файл **без суффикса** — это Role; остальные —
  с суффиксом типа (`.SKILL`, `.BEHAVIOR` и т.д.). Правила —
  [entity-taxonomy.md](../guidelines/entity-taxonomy.md), §7.

**Имя темы.** Составные темы — через тире: `it-llm`, `it-qa`. Не через
точку (ломает иерархию в IDE и скриптах). Дефис — рабочее решение; при
росте числа IT-тем (>6) рассмотреть переход на `it/` с подпапками.


============================================================
## Как использовать

**Найти всё для темы.** Зашёл в `prompt-by-theme/<тема>/` — видишь все
артефакты темы, сгруппированные по типу.

**Собрать композит для темы.** Берёшь Role из темы, add-on — из темы или
из `prompts/` (если общий). Собираешь по правилам
[composite-assembly.md](../guidelines/composite-assembly.md).

**Добавить артефакт в тему.** Проверь: ≥2 артефакта? Связь устойчива?
Если да — можно создавать тему или добавлять в существующую. Если нет —
файл живёт в `prompts/<сущность>/`.


============================================================
## Пример

```
prompt-by-theme/psychology/
  actions/
    user-database/
    Контекстный-снимок.Психотерапия.txt
    Моментальная-карта-сессии.txt
    Сегментация-терапевтического-диалога.txt
  Критический-анализ-в-психологии.SKILL.txt
  Психолог-аналитик.txt
```

Здесь:
- **Role** — `Психолог-аналитик.txt` (без суффикса, дефолт в плоском каталоге);
- **Skill** — `Критический-анализ-в-психологии.SKILL.txt` (с суффиксом);
- **Actions** — в подпапке `actions/`, потому что их ≥3;
- **Sidecar** — `.GUIDE.txt` рядом с actions, не считается артефактом.

Тема `psychology/` создана: ≥2 артефакта, устойчивая связь. Композиты
`Психолог.Критик.*.txt` живут в `prompt-composites/`, не здесь.
