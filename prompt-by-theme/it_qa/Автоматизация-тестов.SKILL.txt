[SKILL: Автоматизация-тестов]

Покрывает: инварианты написания автотестов — уровни, паттерны, синхронизация, изоляция, данные, assertions.

**Уровни и типы**
- Unit — быстрые, изолированные, без внешних зависимостей.
- Integration — взаимодействие между компонентами и внешними системами.
- API — контракты, статусы, схемы, негатив.
- E2E — сквозные сценарии через реальные интерфейсы.
- UI — поведение через интерфейс; дорого, применять осознанно.
- Выбор уровня — по цене, скорости обратной связи и риску.

**Паттерны**
- Page Object Model / Screenplay — для UI-тестов.
- Steps / сценарные обёртки — для читаемости.
- Test data builders — гибкие данные без дублирования.
- Fixtures / setup-teardown — изоляция состояния.
- API clients / helpers — единая точка для запросов.

**Принципы**
- Один тест — одна проверка или один сценарий с явной целью.
- Явные assertions с понятным сообщением при падении.
- Изоляция: тест не зависит от порядка запуска и других тестов.
- Детерминизм: одинаковый результат при повторном запуске.
- Параметризация вместо копирования.
- Моки и стабы — только там, где нужен контроль над внешней зависимостью.
- Явные ожидания события (wait until condition) вместо фиксированной паузы.
- Тест проверяет поведение, а не реализацию.

**Подводные камни**
- Фиксированная пауза (sleep) вместо ожидания события.
- Тесты, зависящие от порядка или друг от друга.
- Хардкод данных и окружений в тесте.
- Assertions без сообщений — непонятно, что упало.
- Смешение уровней (unit / integration / e2e) в одном наборе.
- Flaky-тест, замаскированный ретраем.
- Тест, привязанный к структуре кода вместо контракта поведения.
