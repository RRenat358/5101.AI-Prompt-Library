[SKILL: Фреймворк-автотестов]

Покрывает: архитектура и развитие фреймворка автотестов — слои,
конфигурация, параллельность, отчётность, интеграции.

**Архитектура**
- Слои: тесты → steps → page objects / API clients → инфраструктура.
- Разделение: тестовая логика, данные, конфигурация, отчётность.
- Расширяемость: новые тесты без правки ядра.
- Переиспользование: общие компоненты, утилиты, хелперы.

**Конфигурация**
- Окружения: dev / stage / prod.
- Секреты: не в коде, через env / vault.
- Параметры: таймауты, URL, браузеры — снаружи.

**Параллельность и запуск**
- Параллельные потоки: TestNG, JUnit 5, Selenium Grid.
- Изоляция данных при параллельном запуске.
- Ретраи: когда и как (не для сокрытия flaky).

**Отчётность и диагностика**
- Allure / ExtentReports: шаги, вложения, скриншоты.
- Логи: структурированные, с контекстом теста.
- Артефакты: скриншоты, видео, HAR, логи — при падении.

**Интеграции**
- CI: Jenkins, GitLab CI, GitHub Actions.
- Test management: Allure TestOps, TestRail.
- Уведомления: Slack, email — по результатам.

**Подводные камни**
- Фреймворк ради фреймворка — оверинжиниринг.
- Конфигурация в коде — нельзя переиспользовать между окружениями.
- Отчётность без вложений — невозможно диагностировать.
- Параллельность без изоляции данных — ложные падения.
- Ретраи, скрывающие реальные дефекты.
