[SKILL: Фреймворк-автотестов]

Покрывает: архитектура и развитие фреймворка автотестов — слои, конфигурация, параллельность, отчётность, интеграции.

**Архитектура**
- Слои: тесты → steps / сценарии → клиенты (UI, API) → инфраструктура.
- Разделение: тестовая логика, данные, конфигурация, отчётность.
- Расширяемость: новый тест — без правки ядра.
- Переиспользование: общие компоненты, утилиты, хелперы.
- Границы: тест не знает о деталях инфраструктуры.
- Простота: фреймворк ради фреймворка — структурный риск (сложность растёт быстрее, чем польза).

**Конфигурация**
- Окружения: dev / stage / prod — переключаются, не дублируются.
- Конфигурация снаружи кода: свойства, переменные окружения, конфигурационные файлы; в коде — только дефолты.
- Секреты: не в коде, через переменные окружения или хранилище секретов.
- Параметры: таймауты, URL, окружения — снаружи кода.
- Один источник правды на параметр.

**Параллельность и запуск**
- Параллельность на уровне фреймворка и на уровне инфраструктуры.
- Изоляция данных при параллельном запуске — обязательна.
- Ретраи: только для нестабильных внешних зависимостей, не для сокрытия flaky.

**Отчётность и диагностика**
- Шаги теста, вложения, скриншоты, логи — при падении.
- Логи структурированные, с контекстом теста.
- Артефакты диагностики: скриншоты, видео, сетевые дампы, логи сервисов.

**Интеграции**
- CI: запуск, статусы, публикация отчётов.
- Test management: публикация результатов.
- Уведомления: по результатам прогона.
