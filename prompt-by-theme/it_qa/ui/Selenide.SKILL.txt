[SKILL: Selenide]

Покрывает: высокоуровневую автоматизацию браузера через Selenide — smart waits,
chain API, разумные дефолты, диагностика из коробки.

**Философия и место в экосистеме**
- Selenide — обёртка над Selenium с разумными дефолтами: ожидания, ретраи, снимки при падении — включены по умолчанию.
- Модель мышления: «селектор → действие/проверка» в одной цепочке, без ручных ожиданий в типичном случае.
- Selenide не заменяет Selenium полностью: низкоуровневый доступ к WebDriver остаётся доступен, когда высокоуровневого не хватает.
- Следствие: код короче, но меньше явного контроля; понимать, что происходит под капотом, обязательно.

**Модель селектор-действие**
- Селектор — это описание элемента, а не найденная ссылка; поиск происходит в момент действия/проверки.
- Цепочка: селектор → действие или проверка условия.
- Коллекции: работа с множествами элементов, фильтрация, извлечение значений.
- Действия и проверки — разделены: действие меняет состояние, проверка утверждает ожидание.
- Селекторы композируются: поиск внутри найденного, фильтрация по условию.

**Conditions (условия)**
- Стандартные категории: видимость, доступность, текст, атрибут, количество, наличие/отсутствие.
- Условие — декларативное описание ожидаемого состояния, а не процедура ожидания.
- Кастомные условия — когда стандартных не хватает; собираются как композиция или собственное условие.
- Проверки (should) и действия с ожиданием — разные операции; выбирать осознанно.

**Smart waits**
- Ожидание встроено в действия и проверки: не нужно писать явные waits в типичном случае.
- Дефолтный таймаут — глобальная настройка; локальное переопределение — осознанно, для конкретного случая.
- Smart waits покрывают большинство гонок, но не все: сложные условия (сеть, анимация, стабильность) могут требовать явного поведения.
- Когда auto-wait маскирует проблему: если тест «иногда падает» — разбираться в причине, а не увеличивать таймаут.

**Конфигурация**
- Глобальные настройки: базовый URL, браузер, таймауты, снимки при падении, отчёты, headless.
- Конфигурация — снаружи кода теста: свойства, переменные окружения, конфигурационные файлы.
- Один источник правды на параметр; окружения переключаются, не дублируются.
- Настройки браузера (опции, профили) — через конфигурацию, не в тесте.

**Коллекции**
- Работа с множествами: размер, тексты, фильтрация, проверка каждого.
- Ленивость: коллекция — описание, а не снимок; операции вычисляются при обращении.
- Фильтрация по условию — декларативно; избегать ручных циклов там, где есть встроенное.

**Когда спускаться к Selenium**
- Нужен низкоуровневый контроль: точные ожидания, работа с драйвером, нестандартные взаимодействия.
- Selenide даёт доступ к нижележащему WebDriver — использовать осознанно, понимая, что выходишь из «умных дефолтов».
- Смешение высокоуровневого и низкоуровневого в одном тесте — норма, но границы должны быть явными.

**Диагностика**
- Снимки при падении — по умолчанию; настройка — глобальная.
- Снимки не отключать ради скорости: диагностика при падении ценнее сэкономленных секунд.
- Сообщение об ошибке содержит селектор и ожидаемое условие — ценно для диагностики.
- Логи браузера и снимок DOM — доступны, но требуют настройки (в отличие от снимков).
- Контекст ошибки: селектор, условие, URL, браузер — часть сообщения.

**Best practices**
- Доверять дефолтам; переопределять осознанно и локально.
- Селекторы — семантические и стабильные; не позиционные.
- Проверки через conditions, не через ручные ожидания.
- Конфигурация — снаружи кода.
- Спускаться к Selenium API только когда высокоуровневого не хватает.
- Диагностика при падении — оставить включённой, не отключать ради скорости.
