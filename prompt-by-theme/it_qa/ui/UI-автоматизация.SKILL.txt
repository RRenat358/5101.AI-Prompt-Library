[SKILL: UI-автоматизация]

Покрывает: инварианты автоматизации через пользовательский интерфейс —
синхронизация, локаторы, состояния, изоляция, диагностика.

**Когда UI-автоматизация уместна**
- UI-тест — для того, что видно только через интерфейс: пользовательские сценарии, интеграция фронта и бэка, визуальное поведение.
- Если проверку можно сделать через API — делать через API: быстрее, стабильнее, дешевле в поддержке.
- Пирамида: много unit, меньше API, ещё меньше UI; UI — верхушка, не основа.

**Синхронизация с UI**
- Ожидание состояния элемента, а не фиксированное время.
- Явные ожидания конкретного условия: появление, исчезновение, изменение текста, стабильность.
- Уровни ожиданий: явные в тесте, неявные в инструменте — понимать разницу и не смешивать.
- Ожидание перед действием и после действия.
- Сложные условия: комбинация состояний, ожидание сети, ожидание анимации.
- Flaky-тест — сигнал разобраться в причине; увеличение таймаута или ретрай
  без разбора маскирует дефект и теряет доверие к тестам.

**Локаторы**
- Приоритет стратегий: семантические атрибуты (role, label, alt) → тестовые атрибуты (data-testid) → CSS → XPath.
- Локатор описывает смысл, а не позицию в DOM.
- Привязка к тексту — только для стабильных, контролируемых строк.
- Тестовые атрибуты — когда семантики нет, но поведение стабильно.
- XPath по структуре — последнее средство; ломается при изменении вёрстки.

**Локатор, действие, состояние — три операции**
- Найти элемент — получить ссылку или дескриптор.
- Действовать на элемент — клик, ввод, наведение.
- Проверить состояние элемента — видим, активен, присутствует, стабилен, прикреплён.
- Разделять эти операции в коде и в мышлении; не смешивать проверку с действием.

**Состояния элемента**
- Присутствует в DOM (attached).
- Видим (visible).
- Доступен для взаимодействия (enabled / clickable).
- Стабилен: не движется, не перерисовывается.
- Содержит ожидаемое значение: текст, атрибут.
- Действие допустимо только в подходящем состоянии — иначе гонка.
- Stale element — именованная категория: DOM изменился между поиском и действием, ссылка устарела;
  структурное свойство DOM, не баг инструмента. Лечится пере-поиском после изменения DOM.

**Состояние и изоляция**
- Каждый тест начинает с чистого состояния: cookies, сессии, localStorage, кэш.
- Вход и выход не оставляют побочных эффектов.
- Изоляция через профили, контексты или отдельные инстансы браузера.
- Параллельный запуск — изоляция состояния обязательна.

**Кросс-браузерность и разрешения**
- Матрица конфигураций — только то, что реально различается.
- Не все тесты должны идти во всех браузерах: smoke — в основном, полный набор — в одном.
- Разрешение экрана влияет на видимость и локаторы; фиксировать в конфигурации.

**Визуальная регрессия**
- Сравнение с baseline — управление шумом: динамический контент, время, анимации.
- Обновление baseline — осознанно, с ревью.
- Не заменяет функциональные тесты.

**Диагностика при падении**
- Скриншот, снимок DOM, логи браузера, сетевые запросы — автоматически при падении, не по запросу.
- Локатор и состояние элемента — в сообщении об ошибке.
- Окружение: браузер, версия, разрешение, URL — для воспроизведения.
