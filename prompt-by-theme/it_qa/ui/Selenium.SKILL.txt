[SKILL: Selenium]

Покрывает: низкоуровневую автоматизацию браузера через WebDriver — дисциплина
ожиданий, жизненный цикл элемента, окружение страницы, диагностика.

**Архитектура и модель**
- WebDriver — стандартизированный протокол «клиент → драйвер → браузер».
- Клиент (тест) шлёт команды; драйвер управляет браузером; браузер выполняет.
- Каждая команда — сетевое взаимодействие: цена выше, чем у in-process инструментов.
- Selenium даёт голый контроль без дефолтов: ожидания, ретраи, изоляцию и диагностику настраиваешь сам.
- Следствие: код на Selenium по умолчанию склонен к гонкам; дисциплина ожиданий — не опция, а необходимость.

**Дисциплина ожиданий**
- Явные ожидания (explicit waits) — норма: ждать конкретное условие перед действием и после.
- Неявные ожидания (implicit waits) — глобальный таймаут поиска; структурно
  конфликтуют с явными: смешение даёт непредсказуемые таймауты.
- Фиксированные паузы — анти-паттерн: не гарантируют готовность и замедляют прогон.
- Ожидание — это условие на состоянии (появился, исчез, стал видим, изменился текст), а не «подождать N секунд».
- Сложные условия: комбинация состояний, ожидание стабильности, ожидание сетевой активности — собираются как кастомные условия.
- Ожидание перед действием и ожидание последствий действия — разные вещи; нужны оба.

**Жизненный цикл элемента**
- Элемент — это ссылка на узел DOM в момент поиска, а не на «место в интерфейсе».
- Если DOM изменился между поиском и действием — ссылка устаревает (stale element). Структурное свойство WebDriver, не баг.
- Правило: найти → дождаться нужного состояния → действовать; после навигации или изменения DOM — искать заново.
- Держать ссылку на элемент между действиями — источник гонок.
- «Элемент не интерактивен» (not interactable) — часто не про элемент,
  а про его состояние: перекрыт, невидим, вне вьюпорта, анимируется.
- Прежде чем действовать — проверить состояние: видим, enabled, стабилен, не перекрыт.

**Локаторы**
- By-стратегии: id, name, cssSelector, xpath, className, linkText.
- Приоритет: id (если стабилен) → css по смыслу → xpath по смыслу; позиционные и структурные — последнее средство.
- CSS быстрее и читаемее XPath для большинства задач; XPath — когда нужен обход вверх по дереву или сложное условие.
- Локатор — часть теста; его стабильность важнее краткости.

**Окружение страницы**
- iframe: переключение контекста обязательно; забыл вернуться — следующие поиски не найдут элементы.
- Alerts / confirm / prompt: переключение на диалог, принятие/отклонение, возврат к странице.
- Окна и вкладки: управление дескрипторами, переключение, закрытие; дескриптор — не индекс.
- JavaScript-executor: когда нативного API не хватает (скролл, клик по
  перекрытому элементу, чтение состояния) — осознанно, с пониманием, что это обход, а не норма.

**Управление браузером**
- Опции и capabilities: headless, профили, расширения, размеры окна, user-agent.
- Профиль — состояние браузера; переиспользование профиля между тестами нарушает изоляцию.
- Драйверы: версия драйвера должна соответствовать браузеру; управление версиями — часть инфраструктуры, не теста.
- Изоляция: каждый тест — чистое состояние (профиль, cookies, кэш).

**Page Object в стиле Selenium**
- Page Object инкапсулирует локаторы и действия страницы; тест работает со смыслами, не с селекторами.
- Локаторы — внутри Page Object; тест не знает о DOM.
- Действия возвращают Page Object следующей страницы или результат.
- Ожидания — внутри Page Object или в предусловиях теста, не размазаны по тесту.
- Page Factory — один из способов организации; не обязателен, выбирается осознанно.

**Диагностика**
- Нативно Selenium даёт мало: скриншоты, логи браузера, логи драйвера — доступны, но не автоматизированы.
- Скриншот при падении — настраивается в обёртке/хуках, не в самом тесте.
- Логи браузера (console) — ценны для диагностики JS-ошибок.
- Снимок DOM на момент падения — важнее скриншота для понимания локаторов.
- Контекст ошибки: локатор, состояние элемента, URL, браузер, версия — часть сообщения, не отдельный лог.

**Best practices**
- Явные ожидания по умолчанию; неявные — не использовать или использовать осознанно и без смешения.
- Пере-поиск элемента после навигации и изменения DOM.
- Проверка состояния перед действием.
- Изоляция через опции и профили; чистое состояние на тест.
- Page Object для структуры; локаторы — внутри страниц.
- Диагностика при падении — автоматически, с контекстом.
