[SKILL: Playwright]

Покрывает: современную автоматизацию браузера через Playwright — auto-waiting,
browser contexts, семантические локаторы, сеть, trace-диагностика.

**Архитектура: browser → context → page**
- Browser — инстанс браузера; context — изолированная сессия внутри браузера; page — вкладка/страница внутри контекста.
- Контекст — единица изоляции: cookies, storage, кэш, разрешения — свои на каждый контекст.
- Контексты дешевле, чем отдельные браузеры: изоляция без цены запуска браузера.
- Следствие: изоляция тестов — через контексты, а не через профили и перезапуск браузера.
- Параллельные тесты — каждый в своём контексте; общий браузер допустим.

**Философия локаторов**
- Семантические локаторы — первый выбор: по роли, метке, тексту, test-id, placeholder.
- Семантический локатор описывает, как пользователь или screen reader видит элемент, а не как устроен DOM.
- CSS и XPath доступны, но — последнее средство; семантика устойчивее к изменениям вёрстки.
- Локаторы композируются: фильтрация, поиск внутри, цепочки.

**Auto-waiting и actionability**
- Перед действием Playwright проверяет «готовность» элемента: видим, стабилен, enabled, не перекрыт, принимает события.
- Auto-waiting покрывает типичные гонки; не нужно писать явные ожидания в обычном случае.
- Что не покрывает: сетевые условия, бизнес-состояния, анимации за пределами проверок actionability — для них явные ожидания.
- Когда auto-wait маскирует проблему: «иногда падает» — разбираться в причине, а не полагаться на ретраи.
- Явные ожидания — не «подождать N секунд», а «дождаться условия» (ответ, событие, состояние).

**Сеть**
- Перехват запросов и ответов — архитектурная возможность: мокирование, подмена, наблюдение.
- Ожидание сетевых событий — явное условие, не пауза.
- Мокирование — для изоляции от внешних систем и для воспроизведения редких сценариев.
- Наблюдение за сетью — часть диагностики: что ушло, что вернулось, что упало.

**Диагностика: trace**
- Trace — запись всего прогона: действия, снимки DOM, сеть, консоль, скриншоты по шагам.
- Trace — архитектурная фича, а не надстройка: включается на уровне конфигурации, читается как временная шкала.
- Trace включён в CI: отключение ради скорости экономит минуты, но падение без trace не диагностируется — цена выше экономии.
- Снимок DOM на каждом шаге — важнее скриншота для понимания локаторов.
- Контекст ошибки: локатор, состояние, шаг, сеть — в trace.

**Параллелизация и изоляция**
- Workers — параллельные процессы; каждый со своим браузером и контекстами.
- Sharding — распределение тестов между машинами.
- Изоляция через контексты: состояние одного теста не влияет на другой.
- Данные — изолированы на тест; параллельность без изоляции данных даёт ложные падения.

**Мультиязычность**
- Одна архитектура и одна философия — разные синтаксисы в разных языках.
- Общее: локаторы, auto-waiting, контексты, сеть, trace.
- Различия: async/await в одних языках, синхронный стиль в других; обработка промисов, типизация.
- Async/await: неприменённый await — гонка в коде теста (действие не дождалось); лишний await — потеря параллельности.
  Структурный риск async-языков.
- При переходе между языками — переносится мышление, не код.

**Best practices**
- Семантические локаторы по умолчанию.
- Доверять auto-waiting, но знать его границы.
- Явные ожидания — для сетевых и бизнес-условий.
- Изоляция через контексты, не через перезапуск браузера.
- Trace включён в CI; читать trace при падении.
- Мокирование — для внешних зависимостей, не для того, что тестируешь.
- Параллельность с изоляцией данных.
