[SKILL: Тест-дизайн]

Покрывает: проектирование тест-кейсов и чек-листов на основе тестовых условий.

**Техники**
- Классы эквивалентности и граничные значения.
- Таблицы решений, попарное тестирование (pairwise), комбинаторика.
- Диаграммы состояний и переходов.
- Сценарии использования (use cases), сквозные сценарии.
- Позитивные и негативные сценарии.
- Risk-based test design: приоритизация по вероятности и влиянию.
- Configuration testing: дизайн под матрицу конфигураций (ОС, версии, окружения).
- Data-driven test design: наборы данных для API/БД, границы и аномалии.
- Contract-based test design: проверки схемы, совместимости, версионирования API.

**Принципы**
- Явный ожидаемый результат в каждом тест-кейсе.
- Минимизация дублирования покрытия.
- Выбор формы: тест-кейс (формальный, повторяемый) или чек-лист (гибкий, для опытного тестировщика).

**Подводные камни**
- Покрытие только позитивом.
- Тест-кейсы без ожидаемого результата.
- Дублирующие проверки под разными именами.
- Отсутствие граничных значений.
- Смешение уровней (юнит/интеграция/e2e) в одном наборе.
- Data-driven без контроля над данными — тесты ломаются на окружении.

============================================================
