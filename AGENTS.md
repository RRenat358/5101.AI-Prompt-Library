# AGENTS.md — инструкция для AI-ассистентов и контрибьюторов

Этот файл — для агентов и людей, которые работают с репозиторием. Кратчайшая
карта: что читать, где искать, как добавлять. Полные правила — в гайдах, здесь
только маршрут.

**Сначала прочитай [entity-taxonomy.md](guidelines/entity-taxonomy.md).** Это
словарь, на котором построено всё остальное. Без него гайды будут
противоречить друг другу в голове.


============================================================
## 1. Приоритет правил

Правила этого репозитория приоритетнее твоих дефолтных практик оформления.
При конфликте — следуй репозиторию. При неясности — спроси.


============================================================
## 2. Карта

Корень репозитория — плоский, агент обойдёт дерево сам. Что где:

```
archive                   # разобранное и устаревшее
docs                      # справочные материалы
guidelines                # правила и гайды
prompt-by-theme           # тематические витрины
prompt-composites         # собранные сборки
prompt-snippets           # общие сниппеты
prompt-wrappers           # контейнеры
prompts                   # единичные сущности
  actions/
  behaviors/
  formats/
  roles/
  skills/
```


============================================================
## 3. Поиск

1. **Мета-блок.** У каждого файла — шапка с `tags`, `description`, `title`.
   Сканируй их первым делом.
2. **Имя и место.** Суффикс (`.SKILL`, `.BEHAVIOR`, `.ROLE`…) и каталог
   говорят о типе. Без суффикса в своей папке — дефолт этой папки.
3. **Заголовки блоков.** Если меты нет — читай заголовки (`[ЯДРО РОЛИ]`,
   `[КОМПЕТЕНЦИИ РОЛИ]` и т.д.), они скажут тип.
4. **Спроси.** Один уточняющий вопрос дешевле, чем переименовать файл в
   неправильное место.


============================================================
## 4. Создание и редактирование

Маршрут, без раскрытия сути — за деталями иди по ссылкам.

1. **Тип.** Action, Behavior, Composite, Format, Role, Skill, Wrapper, Snippets,
   Guide. Не подходит ни один — вероятно, мусор или сборник (см. §6b
   [entity-taxonomy.md](guidelines/entity-taxonomy.md)).
2. **Место.** Своя папка (`prompts/skills/`) или `prompt-by-theme/<тема>/`.
   Правила темы — §6a [entity-taxonomy.md](guidelines/entity-taxonomy.md).
3. **Имя.** В своей папке — без суффикса. В плоском каталоге или чужой папке —
   с суффиксом типа (капсом). Полные правила именования (включая язык,
   разделители, `.en`) — [style.md](guidelines/style.md).
4. **Мета-блок.** [style.md](guidelines/style.md),
   [tagging-system.md](guidelines/tagging-system.md).
5. **Оформление.** [headers.md](guidelines/headers.md),
   [visual-separators.md](guidelines/visual-separators.md).
6. **Гайд для человека.** Sidecar `<имя>.GUIDE.txt` рядом с мишенью — §8
   [entity-taxonomy.md](guidelines/entity-taxonomy.md).

Полный чек-лист — §9 [entity-taxonomy.md](guidelines/entity-taxonomy.md).

## 5. Ловушки

Короткие указатели на частые ошибки. Наткнулся — иди по ссылке.

- **Behavior не содержит «Ты — …».** Содержит — это Role-версия, её место в
  композите или в чужой папке с суффиксом `.ROLE`. §5
  [entity-taxonomy.md](guidelines/entity-taxonomy.md).
- **Одна стойка на композит.** Две — это не композит, а другая роль.
  [stance-and-skills.md](guidelines/stance-and-skills.md).
- **Двойник — только с меткой синхронизации** в шапке обоих. §3
  [entity-taxonomy.md](guidelines/entity-taxonomy.md).
- **Composite — версии в шапке:** версия сборки и версии встроенных add-on.
  [prompt-composites/README.md](prompt-composites/README.md).
- **Инородец в чужой папке — с суффиксом своей сущности.** В `behaviors/`
  дефолт — Behavior, Role там — `.ROLE`. §7
  [entity-taxonomy.md](guidelines/entity-taxonomy.md).

- [ ] Если двойник — метка синхронизации в обоих?
