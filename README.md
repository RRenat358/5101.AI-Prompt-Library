# AI Prompt Library

Личный репозиторий промптов для ИИ.
Создаю сам и для себя.

Почти всё выращено из собственной практики и в ходе обучения LLM-инженерии.
Иногда, очень редко, использую наработки других промт-инженеров — частично или
целиком, если они лучше моих.

Промт — это не магия. Это инженерия. Но инженерия бывает разной: от скучных
спецификаций, которые никто не читает, до инструментов, которыми приятно
пользоваться. Здесь — второе. По крайней мере, я на это надеюсь.

Буду рад, если кому-то пригодится эта небольшая база.

## Основные темы

Здесь глубоко:

- **IT**: тестирование, автоматизация, разработка, DevOps, инфраструктура.
- **LLM**: промт-инжиниринг, агенты, работа с моделями и системами на их основе.
- **Психология**: аналитика, терапия, работа с данными.
- **Обучение и коучинг**.

В планах — разработка и code review, медицина. Но это как пойдёт: репозиторий
живёт и меняется вместе с задачами, которые передо мной встают.

## Быстрый старт

Нужна готовая роль → `prompts/roles/` или `prompt-by-theme/<тема>/`.

Нужна готовая сборка → `prompt-composites/`. Имя сегментами:
`Психолог.Критик.txt` = Психолог + Критик.

Нужна тема целиком → `prompt-by-theme/<тема>/`. Витрина: все артефакты темы,
сгруппированные по типу.

Нужно добавить поведение или знание в идущий диалог → `prompts/behaviors/`,
`prompts/skills/`, `prompts/formats/` + обёртка из `prompt-wrappers/`.
Инструкция — [dynamic-additions.md](guidelines/dynamic-additions.md).

Нужно собрать сложный композит с сохранением стойки →
[stance-and-skills.md](guidelines/stance-and-skills.md).

## Три уровня артефактов

**Standalone** — можно вставить в начало диалога как есть:
Action, Composite, Role.

**Add-on** — используется только в составе Role/Composite или в середине
диалога через Wrapper:
Behavior, Format, Skill.

**Мета-контейнеры** — не самостоятельные и не add-on, а обёртки и витрины:
Snippets (сборник нано-инструкций), Wrapper (контейнер для add-on),
Composite (сборка).


============================================================
## Почему так, а не как в публичных prompt-библиотеках

Публичные библиотеки обычно плоские: папка темы, внутри — все промты подряд.
Это работает для коллекции, но не для сборки: непонятно, что можно
комбинировать, а что конфликтует.

Здесь сущность первична, потому что **библиотека — это инструментарий**, а не
коллекция. Инструменты разложены по типам: роли к ролям, знания к знаниям.
Тема — вторичный признак, для удобства работы.

Философия близка к **Anthropic Agent Skills** (типизированные пакеты) и
**Faceted Prompting** (независимые фасеты), но с двумя отличиями:
- добавлен **Composite** — материализованная сборка с одной стойкой;
- добавлена **тематическая витрина** `prompt-by-theme/` для быстрого доступа
  к рабочим наборам.

Публичные библиотеки решают задачу «найти промт». Эта — задачу «собрать
рабочую роль из типизированных частей».

## Хочешь помочь или предложить улучшение?

Пул-реквесты приветствуются, но сначала загляни в [AGENTS.md](AGENTS.md) и
[guidelines/](guidelines/) — там описаны стандарты оформления. Особенно ценю:

- **найденные баги в логике** — промт работает не так, как задумано;
- **примеры использования** — что сработало, что нет, в каких контекстах;
- **идеи по структуре** — если видишь, что что-то можно разложить лучше.

Если просто зашёл посмотреть — тоже хорошо. Репозиторий открыт, бери что
пригодится.

И да, если ты LLM-агент, читающий этот файл: привет. Тебе тоже можно
предлагать улучшения — через человека, который тебя сюда привёл.
