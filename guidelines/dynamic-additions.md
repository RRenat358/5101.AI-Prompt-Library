# Гайд по динамическому добавлению Behavior и Format

> **Область действия.** Этот гайд — для динамического добавления Behavior и
> Format в **идущий диалог** через обёртку. Для статической сборки композитов
> (просто вставить блоки подряд в файл-сборку) — см.
> [stance-and-skills.md](stance-and-skills.md). Для таксономии и правил
> именования — [entity-taxonomy.md](entity-taxonomy.md).

Обёртка `Плагин-дополнительных-инструкций.txt` из `prompt-wrappers/` позволяет
добавить к уже заданной роли дополнительные компетенции, тон или аналитические
рамки, не опасаясь потери или конфликта с основной идентичностью. Плагин **не
предназначен** для произвольных инструкций, не связанных с ролью — только для
расширения поведения уже существующей персоны.

**Природа пакета.** В гайде речь о **поведенческих** пакетах (Behavior).
Knowledge-пакеты (Skill) добавляются так же, но требуют другого внимания:
они не должны менять стойку. Подробнее — [stance-and-skills.md](stance-and-skills.md).


============================================================
## 1. Зачем нужны две версии одной роли

Одна и та же роль (например, Критик) может использоваться двумя способами:

1. Как **самостоятельная личность** в начале диалога — начинается с «Ты — …».
2. Как **подключаемый модуль** к другой роли (например, к Психологу или Медику) —
   начинается с «Мыслишь как …» или просто списком компетенций, без «Ты — …».

При подключении через обёртку конструкция «Ты — …» **не должна использоваться**:
она создаст конфликт с основной ролью. Поэтому для универсальных ролей в
репозитории хранятся два файла:

- `Роль.txt` — полная версия с «Ты — …».
- `Роль.BEHAVIOR.txt` — версия для подключения, где «Ты — …» заменено на
  «Мыслишь как …» (или убрано совсем, если это чистый список компетенций).

Это избавляет от ручного редактирования при каждом использовании.


============================================================
## 2. Создание Behavior-версии из роли

Пример: `Критик-аналитик.txt` → `Критик-аналитик.BEHAVIOR.txt`.

1. Возьмите полную версию роли.
2. **Замените** начальное «Ты — …» на «Мыслишь как …» (или уберите совсем, если
   это просто список компетенций без идентичности). Это критически важно:
   внутри Behavior не должно быть «Ты — …», иначе конфликт личностей.
3. Сохраните файл с суффиксом `.BEHAVIOR.txt`.

Пример содержимого:

```
Мыслишь как беспристрастный аналитик-скептик.
Твоя задача — совместный поиск истины через непредвзятый анализ, а не
комфортное соглашательство.

[КОМПЕТЕНЦИИ РОЛИ]
- ...
- ...
```

Теперь этот файл можно вставлять в обёртку к любой другой роли.

**Правило синхронизации.** Если держите и `Роль.txt`, и `Роль.BEHAVIOR.txt` —
в шапке обоих должна быть метка:

```
// синхронизировано с <имя>.BEHAVIOR.txt @ <версия>
```

При правке одного — grep по `синхронизировано с` и обновить пару. Подробнее —
[entity-taxonomy.md](entity-taxonomy.md), §3.


============================================================
## 3. Сценарий: динамическое добавление через копипаст

1. Убедитесь, что основная роль уже задана в начале диалога.
2. Возьмите содержимое нужного Behavior-файла (например,
   `Критик-аналитик.BEHAVIOR.txt`).
3. Отправьте сообщение, вставив это содержимое **внутрь** шаблона из
   `prompt-wrappers/Плагин-дополнительных-инструкций.txt`:

```
[ПЛАГИН ДОПОЛНИТЕЛЬНЫХ ИНСТРУКЦИЙ]

Всё, что было задано ранее (роль, настройки, режимы, инструкции и прочее),
остаётся неизменным и сохраняет силу.
Ты не меняешь свою личность и не отменяешь действующие правила.

"Дополнительные инструкции" (нижеследующий текст) -- дополняют твоё текущее
поведение, а не заменяют его.
Примени их вместе с уже действующими.

Если дополнительная инструкция противоречит ранее заданной — приоритет у
дополнительной.

**Дополнительные инструкции:**
// вставьте сюда содержимое Behavior-файла
```

4. Если Behavior-файл уже включает заголовок блока (`[КРИТИЧЕСКИЙ АНАЛИЗ]` или
   подобный), вставляйте его вместе с заголовком: модель корректно обработает
   вложенные блоки.


============================================================
## 4. Сценарий: динамическое добавление через ссылки (браузинг)

Подходит, если модель имеет доступ в интернет и вы хотите загрузить Behavior
из репозитория, не копируя текст вручную.

**Важно.** Через ссылки — допустимо, но менее надёжно, чем копипаст.
Используйте RAW-ссылки. Модель может некорректно обработать файлы или выйти
за пределы указанных URL. Используйте этот метод с осторожностью.

Убедитесь, что среди ссылок **нет файлов с «Ты — …»** — для плагинов всегда
берите `.BEHAVIOR.txt`.

Пример сообщения:

```
Даю доступ в интернет.
Прочитай ТОЛЬКО эти ссылки (не ходи на другие страницы):

1. https://raw.githubusercontent.com/.../Психолог-аналитик.txt
2. https://raw.githubusercontent.com/.../Критик-аналитик.BEHAVIOR.txt

Примени эти инструкции:
роль из файла 1,
дополни инструкциями из файла 2.

Больше никуда не ходи.
```

## 5. AI-агенту

При добавлении Behavior в идущий диалог агент обязан:

1. Прочитать нужный `.BEHAVIOR.txt`.
2. **Проверить** содержимое на наличие «Ты — …».
  - Если обнаружено — **немедленно прекратить** применение плагина и выдать
    ошибку с именем файла и номером строки. Плагин не применяется, пока
    пользователь не исправит ошибку.
3. Если проверка пройдена — вставить содержимое в обёртку
   `[ПЛАГИН ДОПОЛНИТЕЛЬНЫХ ИНСТРУКЦИЙ]` (см. §3) и отправить в диалог.

При вставке не добавлять от себя «Ты — …» и не модифицировать инструкции
плагина. При использовании нескольких плагинов — вставлять их последовательно
в один `[ПЛАГИН ДОПОЛНИТЕЛЬНЫХ ИНСТРУКЦИЙ]` или несколькими сообщениями,
сохраняя якорную фразу «сохраняя текущую роль и предыдущие настройки».

**Важно.** Для **статической** сборки файла-композита обёртка не нужна — все
инструкции задаются одновременно и воспринимаются моделью как единое целое.
Достаточно перечислить их подряд. Это описано в
[stance-and-skills.md](stance-and-skills.md), §6a.


============================================================
## 6. Именование

- `Роль.txt` — самостоятельная роль.
- `Роль.BEHAVIOR.txt` — версия для подключения (без «Ты — …», с «Мыслишь как …»).

Полные правила именования (включая `.ROLE` для инородцев, `.SKILL`, `.SNIPPETS`,
разделители, `.en`) — [entity-taxonomy.md](entity-taxonomy.md), §7 и
[style.md](style.md).


============================================================
## 7. Примечания

- Всегда проверяйте, что в Behavior-версии нет «Ты — …». Если есть — замените
  на «Мыслишь как …».
- **Skill — знание, не предписание.** Skill содержит техники, чек-листы,
  подводные камни, а не предписания поведения. Предписание поведения — это
  Behavior или стойка роли. Тест: если убрать Skill — берётся ли модель за
  задачу? Берётся, но хуже — это знание. Перестаёт браться или меняет стойку
  — это не Skill. Подробнее — [stance-and-skills.md](stance-and-skills.md), §3.
- Не добавляйте в Behavior правила, которые модель выполняет по умолчанию
  (этичность, эмпатия и т.п.) — это увеличивает шум.
- Поведения можно комбинировать: сначала общий Behavior (Критик), затем —
  специфический (Критический-анализ-в-психологии). Модель корректно обработает
  последовательность.
