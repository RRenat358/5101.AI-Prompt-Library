# Таксономия сущностей промт-библиотеки

## Зачем этот файл

Библиотека содержит разнородные артефакты: роли, знания, поведения, форматы,
задачи, контейнеры, сборки. Без фиксированного словаря:
- непонятно, куда класть новый файл;
- непонятно, можно ли использовать файл самостоятельно;
- композиты собираются «на глаз», и стойка уплывает;
- при правке файла неясно, есть ли у него дубль в другом каталоге.

Этот файл задаёт словарь из семи сущностей и правила размещения. Он не заменяет
гайды (`role-plugin-guide.md`, `stance-and-skills-guide.md`), а служит их
основанием.

**Правило первого порядка:** каждый файл имеет ровно один тип из семи. Если файл
не относится ни к одному — это коллекция (разобрать) или мусор (`archive/`).


============================================================
## 1. Семь сущностей

| # | Сущность | Что это | Меняет ли стойку | Самостоятельна |
|---|---|---|---|---|
| 1 | **Role** | Идентичность: «Ты — …» + база (маркеры областей) + стойка | задаёт | да |
| 2 | **Skill** | Знание: техники, чек-листы, подводные камни. Stance-neutral | нет | нет |
| 3 | **Behavior** | Предписание поведения/тона: «мысли как скептик», «будь коллегой» | да (или задаёт тон) | ограниченно (см. §5) |
| 4 | **Format** | Правила оформления вывода: тильда-блоки, структура, разбиение | нет | нет |
| 5 | **Action** | Задача/операция: «создай снимок», «сегментируй диалог», «гуманизируй текст» | нет (задаёт операцию) | да |
| 6 | **Wrapper** | Контейнер для добавления инструкций в идущем диалоге | нет | нет |
| 7 | **Composite** | Материализованная сборка Role + Skill(s) + Behavior(s) + Format(s) + Action(s) | наследует от Role | да |

**Пояснения к таблице.**

- **Role** задаёт стойку — дефолт ответа. Одна роль = одна стойка.
- **Skill** не меняет стойку: убрать → модель всё равно возьмётся за задачу,
  но ответ будет менее глубоким. Это операционный тест.
- **Behavior** может менять стойку (Критик задаёт аналитическую диспозицию) или
  только тон (Коллега). Поэтому «ограниченно самостоятелен» — см. §5.
- **Action** — операция, а не идентичность. Отвечает на «что сделай», не на
  «кто ты». Может содержать встроенные элементы других типов, но первичная
  природа — задача.
- **Wrapper** — контейнер, не самостоятельная единица. Служит для добавления
  add-on в идущем диалоге.


============================================================
## 2. Standalone vs add-on

**Standalone** (используется в начале диалога как есть):
- Role
- Action
- Composite

**Add-on** (используется только в составе Role/Composite или в середине диалога
через Wrapper):
- Skill
- Behavior
- Format

**Wrapper** — особый случай: контейнер, не самостоятельная единица.

**Практическое следствие:** статус определяется каталогом и суффиксом, не
содержимым. Файл в `skills/`, `behaviors/`, `formats/`, `wrappers/` — add-on.
Файл в `roles/`, `actions/`, `composite-prompts/` — standalone.


============================================================
## 3. Одна сущность = один файл = один тип

Два файла с почти одинаковым содержимым, где один — «роль», другой — «плагин»,
создают ловушку: правишь один, забываешь другой.

**Правило:** если содержимое одно, а нужны обе формы — выберите одну первичную,
вторая форма — тонкая обёртка.

- Для поведений (Критик, Коллега) первичная форма — Behavior. Standalone-версия —
  Composite из минимальной обёртки + Behavior (3 строки, без дублирования).
- Для ролей первичная форма — Role. Добавочная форма — та же роль без «Ты — …»,
  но тогда рассинхронизация неизбежна; это цена выбора.


============================================================
## 4. Одна стойка на композит

В композите — ровно одна стойка (Role). Добавление Behavior допустимо, если он
не меняет стойку (Критик на Психологе — ок; Безопасник на Сисадмине — не ок,
это вторая стойка). Подробнее — `stance-and-skills-guide.md`.


============================================================
## 5. Behavior как самостоятельная рамка

Behavior используется и как add-on, и как самостоятельная диспозиция. Чтобы не
держать двух версий:

- Первичный файл — `_shared/behaviors/<имя>.Behavior.txt`, форма «Мыслишь как …».
- Самостоятельная версия — `composite-prompts/<имя>.Standalone.txt`:
  минимальная обёртка («Ты — ассистент») + полный текст Behavior.
- При правке Behavior композит пересобирается; содержание не дублируется.

**Правило:** Behavior никогда не содержит «Ты — …». Идентичность добавляется
вне Behavior, в композите.


============================================================
## 6. Организация: тема первична, общее — в `_shared/`

**Принцип.** Библиотека организована по темам, потому что работа ведётся по
темам. Внутри темы — сущности. Общие сущности, переиспользуемые между темами, —
в `_shared/`.

```
prompts/
  _shared/
    behaviors/
    formats/
    wrappers/
  it/
    actions/
    roles/
    skills/
  psychology/
    actions/
    roles/
    skills/
  writing/
    actions/
    roles/
    skills/
composite-prompts/
guidelines/
docs/
archive/
```

**Почему так.**

- `roles/`, `skills/`, `actions/` тематичны по природе: роль психолога не
  переиспользуется в IT. Держать их в теме — значит видеть всё для темы в одном
  месте.
- `behaviors/`, `formats/`, `wrappers/` универсальны: Критик, тильда-блок,
  обёртка используются везде. Их место — `_shared/`.
- Исключение: тематический Behavior (например, узкая диспозиция только для
  психологии) может лежать в `topic/behaviors/`, но по умолчанию — в `_shared/`.

**Каталоги — строчными буквами, в алфавитном порядке.** Имена файлов — как
принято в языке (русские названия с заглавной).

**Подпапки внутри темы** допустимы, если файлов одного типа по подтеме больше
~5. До этого — плоско.


============================================================
## 7. Правила именования

| Сущность | Суффикс | Пример |
|---|---|---|
| Role | `.Role.txt` или `.Base.txt` | `Сисадмин.Role.txt`, `Разработчик.Base.txt` |
| Skill | `.Skill.txt` | `Security.Auth.Skill.txt` |
| Behavior | `.Behavior.txt` | `Критик-аналитик.Behavior.txt` |
| Format | `.Format.txt` | `Тильда-блок.Format.txt` |
| Action | `.Action.txt` | `Контекстный-снимок.Action.txt` |
| Wrapper | `.Wrapper.txt` | `Плагин-дополнительных-инструкций.Wrapper.txt` |
| Composite | (без суффикса, сегменты через `.`) | `Психолог.Критик.txt` |

Суффикс обязателен для всех, кроме Composite: по имени видно, standalone это
или add-on.


============================================================
## 8. Документация — не промт

`.guide.txt`, `.md`, README, объяснения — это документация, не сущности из §1.
Живут в `guidelines/` или `docs/`, никогда в `prompts/`, `skills/`, `behaviors/`.

Признак: если файл не «вставляется в диалог», а «читается для понимания» — это
документация.


============================================================
## 9. Чек-лист при добавлении файла

- [ ] Тип определён (Role / Skill / Behavior / Format / Action / Wrapper / Composite)?
- [ ] Standalone или add-on? (§2)
- [ ] Файл лежит в каталоге своего типа и своей темы?
- [ ] Имя оканчивается на суффикс типа (кроме Composite)?
- [ ] Если Behavior — нет «Ты — …»? (§5)
- [ ] Если Skill — stance-neutral? (тест: убрать → модель берётся за задачу)
- [ ] Если Action — первичная природа операция, а не идентичность?
- [ ] Если Composite — стойка одна? Версии встроенных add-on в шапке?
- [ ] Нет брата-близнеца в другом каталоге? (§3)
- [ ] Тема проставлена каталогом, а не тегом-папкой? (§6)
