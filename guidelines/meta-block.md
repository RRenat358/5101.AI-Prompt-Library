# Мета-блок: формат и назначение

> **Область действия.** Этот файл описывает мета-блок — шапку промт-файла,
> которая служит для классификации, поиска и навигации. Правила оформления
> тела промта — [style.md](style.md). Типы сущностей —
> [entity-taxonomy.md](entity-taxonomy.md). Теги — [tagging-system.md](tagging-system.md).

Мета-блок — стандартизированная шапка в начале промт-файла: что это, когда
создано, к какой категории относится, что внутри. Без шапки поиск по
репозиторию сводится к угадыванию по имени файла. С шапкой — поиск по тегам,
версиям, описанию. Для агента это дешёвая навигация, для человека — быстрый
обзор.


============================================================
## 1. Защита от «загрязнения» контекста

Мета-блок помечен как «не читать», и LLM, как правило, его пропускает при
работе. Но это **не 100% гарантия**: модель читает файл целиком, и метка —
это инструкция, которую она может проигнорировать. На практике работает как
best-practice: метка снижает шанс, что теги и версии попадут в рабочий контекст,
но не исключает этого полностью.

**AI-ассистент должен:**
- Распознавать мета-блок по открывающей строке.
- Извлекать ключи: `title`, `version`, `tags`, `description` и опциональные.
- Использовать их для поиска, фильтрации, понимания контекста.
- Не включать содержимое мета-блока в цитируемый текст промта при передаче
  в LLM (если пользователь не попросил обратное).

## 2. Формат

```text
[мета: игнорируй всё до второй строки из символов `━`]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
title:        Краткое название
version:      YYYYMMDD-HHMM

tags:         #тип,    #тема,    #статус
description:  Что делает промт
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Открывается строкой `[мета: игнорируй всё до…]` и линией из знаков `━`.
Закрывается **такой же линией той же длины**. Одинаковая длина открывающей и
закрывающей линии закрепляет паттерн: модель видит повтор и точнее распознаёт
границы блока. Используйте стандартные длины (5, 10, 20, 30, 60 знаков) —
частотные паттерны токенизируются эффективнее.

Внутри — пары `ключ: значение` без кавычек. Мета-блок отделён от тела промта
пустой строкой.


============================================================
## 3. Обязательные ключи

### `title`

Человекочитаемое название. Для Composite — состав через ` + `:
`Психолог + Критик + Коллега`.

### `version`

Дата и время последней правки: `YYYYMMDD-HHMM`.
Пример: `20261103-1710` = 3 ноября 2026, 17:10.

Для Composite — самая поздняя из версий встроенных модулей.
Подробнее — [composite-assembly.md](composite-assembly.md), §5.

### `tags`

Классификация. Три группы: тип, тема/область, статус.

```
tags:         #composite, #role,    #psychology,    #ready
```

- **Группа 1 — тип.** `#role`, `#skill`, `#behavior`, `#format`, `#action`,
  `#composite`, `#snippets`, `#wrapper`. Может быть несколько тегов в группе:
  `#composite, #role` — композит, внутри которого роль.
- **Группа 2 — тема/область.** `#it`, `#psychology`, `#writing`, `#llm`,
  `#education`. Может быть несколько.
- **Группа 3 — статус.** Один из: `#draft`, `#tested`, `#ready`, `#archived`.

**Правила:**
- Внутри группы — через запятую. Между группами — таб (4 пробела).
- В группе — **любое количество тегов**, не ограничивайте себя.
- **Три группы обязательны.** После третьей можно добавлять другие группы,
  если это полезно для навигации. Список не закрыт.
- Таб — для человека, чтобы группы читались визуально. Парсер работает и без
  него, но с запятыми — обязательно: `#composite, #role,` — запятая после
  последнего тега в группе.
- Поиск по тегу находит все файлы, где он есть. `#role` найдёт и роли, и
  композиты с ролями — это фича.

Подробнее о тегах — [tagging-system.md](tagging-system.md).

### `description`

Краткое описание сути. Для обычного промта — 1–2 строки: что делает.

Для Composite — состав встроенных модулей:

```
description: |
    Состав:
        1. Психолог-аналитик.txt -- 20260525-1434
        2. Критик-аналитик.txt -- 20261024-1810
        3. Коллега.txt -- 20260526-1510
```

Подробнее о версиях и формате — [composite-assembly.md](composite-assembly.md), §5a.


============================================================
## 4. Опциональные ключи

Список не закрыт: можно вводить свои, если они не дублируют существующие.

- `target-models` — модели, под которые оптимизирован: `[gpt-4o, claude-3.5-sonnet]`.
- `comment` — комментарий для человека. Для многострочного — через `|`.
- `usage` — как использовать: `Вставить в начало диалога первым сообщением`.
- `rules` — правила и ограничения, специфичные для файла.

============================================================
## 6. Если мета-блока нет

Файл считается неклассифицированным. Он работает — LLM прочитает его как
обычный промт. Но найти его поиском по тегам будет нельзя, и агент не поймёт
тип без чтения содержимого.

Для новых файлов мета-блок обязателен. Для старых — желателен: при первой
правке добавьте.
