# Таксономия сущностей промтов

Версия: v1 (черновик)
Назначение: зафиксировать типы сущностей, чтобы гайды и структура каталогов
не противоречили друг другу. Это словарь, а не учебник. Правила сборки — в
`role-plugin-guide.md` и `stance-and-skills-guide.md`.


============================================================
## 1. Шесть сущностей

| Сущность | Что это | Пример | Файл |
|---|---|---|---|
| **Role** | Самостоятельная идентичность: «Ты — …» + база (маркеры) + стойка | Сисадмин, Разработчик | `roles/` |
| **Skill** | Знание: техники, чек-листы, подводные камни. Stance-neutral | Аутентификация, Testing | `skills/` |
| **Behavior** | Предписание поведения: тон, аналитическая рамка, диспозиция | Критик, Коллега | `behaviors/` |
| **Format** | Правила оформления ответа | Тильда-блок, Структурирование | `formats/` |
| **Wrapper** | Контейнер для добавления инструкций в идущем диалоге | Плагин-дополнительных-инструкций | `wrappers/` |
| **Composite** | Материализованная сборка: Role + Skill(s) + Behavior(s) + Format(s) | Психолог.Критик | `composite-prompts/` |


============================================================
## 2. Главное правило: standalone vs add-on

Все шесть сущностей делятся на две категории:

**Standalone** (можно использовать в начале диалога как есть):
- Role
- Composite

**Add-on** (используется только в составе Role или Composite):
- Skill
- Behavior
- Format

**Wrapper** — особый случай: контейнер, не самостоятельная единица.

**Следствие:** каталог сигнализирует статус. Файл в `skills/`, `behaviors/`,
`formats/` — по определению дополнение. Файл в `roles/` или `composite-prompts/` —
самостоятельный. Суффикс `.Плагин` в имени не нужен: путь уже говорит.


============================================================
## 3. Одна сущность = один файл = один тип

**Запрещено:** держать два файла с почти одинаковым содержимым, где один —
«роль», другой — «плагин». Это ловушка обслуживания: правишь один, забываешь
другой.

**Правило:** если содержимое одно и то же, но нужны обе формы использования —
выберите **одну первичную**:

- Первичная — Behavior. Standalone-версия = Composite из минимальной обёртки
  + Behavior (3 строки, без дублирования содержания).
- Первичная — Role. Behavior-версия = та же роль минус «Ты — …». Тогда
  рассинхронизация неизбежна, и это цена выбора.

**Рекомендация:** для поведений (Критик, Коллега) первичная форма —
Behavior. Роль-версия → Composite. Один источник истины, ноль дублей.


============================================================
## 4. Одна стойка на композит

В композите — **ровно одна** стойка (Role). Добавление Behavior допустимо,
если он не меняет стойку (Критик на Психологе — ок; Безопасник на Сисадмине —
не ок, это вторая стойка).

Подробнее — `stance-and-skills-guide.md`.


============================================================
## 5. Организация: сущность первична, тема вторична

Каталог первого уровня — **по типу сущности**, не по теме. Тема — тег в
метаданных (см. `tagging-system.md`), не папка.

**Исключение — подпроект.** Если тема обросла своей инфраструктурой
(гайды, подсистемы, десятки файлов), она становится подпроектом и получает
собственный каталог. Критерий: 5+ файлов одного типа + собственные гайды.
Психология — подпроект. IT — пока тема-тег.

**Подпапки по теме внутри сущности** допустимы, когда файлов одного типа
по одной теме больше ~5. До этого — плоско.

**Запрещено:** категории по фазе использования (`dialog-settings`,
`before-start`, `mid-dialogue`). Фаза — это тег, не тип.


============================================================
## 6. Документация — не промт

Файлы `.guide.txt`, `.md`, README, объяснения — это документация, не
сущности из §1. Живут в `guidelines/` или `docs/`, никогда в `prompts/`,
`skills/`, `behaviors/`.

Признак: если файл не «вставляется в диалог», а «читается человеком или
агентом для понимания» — это документация.


============================================================
## 7. Структура каталогов

~~~
prompts/
  roles/              # standalone, «Ты — …»
    IT/
    psychology/       # подпроект (имеет собственные гайды и подсистемы)
  skills/             # add-on, knowledge
  behaviors/          # add-on, поведение (бывший /mode)
  formats/            # add-on, оформление
  wrappers/           # контейнеры
composite-prompts/    # standalone сборки
guidelines/           # гайды (документация, не промты)
docs/                 # справочные материалы (документация)
archive/              # разобранное / устаревшее
~~~

/mode переименовать в /behaviors. «Mode» — это фаза, а не тип.
/snippets расформировать. Содержимое — по типам из §1. Мусор — в
archive/_inbox/ с правилом: пролежало N недель — удалить.
/dialog-settings расформировать. .guide.txt → docs/; активные
промты — по типам; тег dialog-settings сохраняется в метаданных.

============================================================

8. Чек-лист при добавлении файла
□ Это промт или документация? (документация → guidelines/ или docs/)
□ Какой тип из §1?
□ Standalone или add-on? (§2)
□ Есть ли уже файл с этим содержанием в другой форме? (§3)
□ Если add-on — не меняет ли он стойку? (§4)
□ Куда класть по §7?
□ Тема проставлена тегом, а не папкой? (§5)
============================================================
