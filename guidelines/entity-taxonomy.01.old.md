# Таксономия сущностей промт-библиотеки

## Зачем этот файл

В библиотеке накопились разнородные артефакты, которые исторически назывались
одним словом — «сниппеты», «плагины», «режимы». Из-за этого:
- непонятно, куда класть новый файл;
- непонятно, можно ли использовать файл самостоятельно или только в составе;
- композиты собираются «на глаз», и стойка уплывает;
- при правке одного файла неясно, есть ли у него «брат-близнец» в другом каталоге.

Этот файл фиксирует **шесть сущностей** и правила размещения. Он не заменяет
гайды (`role-plugin-guide.md`, `stance-and-skills-guide.md`), а задаёт словарь,
на котором те построены.

**Правило первого порядка:** каждый файл в библиотеке имеет ровно один тип из
шести. Если файл не относится ни к одному — это либо коллекция (её надо
разобрать), либо мусор (в `archive/`).


============================================================
## 1. Шесть сущностей

| # | Сущность | Что это | Меняет ли стойку | Самостоятельна |
|---|---|---|---|---|
| 1 | **Role** | Идентичность: «Ты — …» + база (маркеры областей) + стойка | задаёт | да |
| 2 | **Skill** | Знание: техники, чек-листы, подводные камни. Stance-neutral | нет | нет |
| 3 | **Behavior** | Предписание поведения/тона: «мысли как скептик», «будь коллегой» | да (или задаёт тон) | ограниченно (см. §5) |
| 4 | **Format** | Правила оформления вывода: тильда-блоки, структура, разбиение | нет | нет |
| 5 | **Wrapper** | Контейнер для добавления инструкций в идущем диалоге | нет | нет |
| 6 | **Composite** | Материализованная сборка Role + Skill(s) + Behavior(s) + Format(s) | наследует от Role | да |

Термины «сниппет», «плагин», «режим», «dialog-settings» — **не сущности**.
Это либо исторические имена (см. §6), либо категории применения.


============================================================
## 2. Правила размещения

**Путь = `<entity>/<domain>/<file>.<Entity>.txt`**

```
prompts/
  roles/
    IT/              Разработчик.Base.txt
    Psychology/      Психолог-аналитик.Role.txt
    ...
  skills/
    IT/              Security.Auth.Skill.txt
    Psychology/      Критический-анализ-в-психологии.Skill.txt
    ...
  behaviors/
    Критик-аналитик.Behavior.txt
    Коллега.Behavior.txt
    ...
  formats/
    Тильда-блок.Format.txt
    Структурирование-ответа.Format.txt
    ...
  wrappers/
    Плагин-дополнительных-инструкций.Wrapper.txt
  ...
composite-prompts/
  ...
```

**Почему сначала сущность, потом тема.** Все skills лежат в одном месте — это
упрощает манифест, поиск, будущую автосборку. Обратный порядок (тема → сущность)
заставляет искать skills по всем тематическим каталогам.

**Домен** — свободная группировка (`IT`, `Psychology`, `Writing`, `Education`).
Домен не является сущностью; это ярлык для навигации. Для файлов без явного
домена — класть в корень соответствующего entity-каталога.


============================================================
## 3. Правила именования

| Сущность | Суффикс | Пример |
|---|---|---|
| Role | `.Role` или `.Base` | `Сисадмин.Role.txt`, `Разработчик.Base.txt` |
| Skill | `.Skill` | `Security.Auth.Skill.txt` |
| Behavior | `.Behavior` | `Критик-аналитик.Behavior.txt` |
| Format | `.Format` | `Тильда-блок.Format.txt` |
| Wrapper | `.Wrapper` | `Плагин-дополнительных-инструкций.Wrapper.txt` |
| Composite | (без суффикса, сегменты через `.`) | `Психолог.Критик.txt` |

Суффикс **обязателен** для всех, кроме Composite. Причина: по имени файла
должно быть видно, самостоятельная это единица или добавка (см. §4).


============================================================
## 4. Самостоятельное vs дополнение — как отличить

**Правило по каталогу:**
- `roles/` и `composite-prompts/` — самостоятельные (используются в начале диалога).
- `skills/`, `behaviors/`, `formats/`, `wrappers/` — добавки (используются
  только в составе или в середине диалога через wrapper).

**Правило по имени:** суффикс `.Skill`, `.Behavior`, `.Format`, `.Wrapper`
однозначно говорит «это добавка». Отсутствие суффикса у файла в `roles/` —
«это роль».

Это и есть ответ на вопрос «как понять, что skill — дополнение»: **по каталогу
и по суффиксу, а не по содержимому**.


============================================================
## 5. Особый случай: Behavior как самостоятельная рамка

Проблема: Критик используется и как самостоятельная рамка («Ты — критик»),
и как добавка к другой роли («Мыслишь как критик»). Хранить две версии —
значит поддерживать «братьев-близнецов» и рассинхронизировать их.

**Решение: единственный источник — Behavior-файл.**

`behaviors/Критик-аналитик.Behavior.txt` написан в форме, которая работает
**и как добавка, и как самостоятельная рамка**:

```
[BEHAVIOR: Критик-аналитик]
Мыслишь как беспристрастный аналитик-скептик.
...
```

- **Как добавка** — вставляется в wrapper или в композит после Role. Работает.
- **Как самостоятельная рамка** — используется в композите
  `composite-prompts/Критик.Standalone.txt`, который состоит из одной якорной
  строки и Behavior:

  ```
  [ЯДРО РОЛИ]
  Ты — ассистент.

  [BEHAVIOR: Критик-аналитик]
  ... (полный текст Behavior) ...
  ```

  Файл-композит — тонкий, поддерживать его дёшево. При правке Behavior он
  подхватывает изменения при пересборке.

**Что это даёт:** нет дублирования содержания. `Критик-аналитик.txt` в
`roles/` больше не нужен — его заменяет `composite-prompts/Критик.Standalone.txt`.

**Правило:** Behavior никогда не содержит «Ты — …». Если для самостоятельного
использования нужна идентичность — она добавляется **вне** Behavior, в
композите.

## 6. Что НЕ является сущностью

| Термин | Что это на самом деле | Куда |
|---|---|---|
| «Сниппет» | Зонтичное слово; так называли и Skill, и Format, и Behavior | отказаться от термина в именах; разобрать по §1 |
| «Плагин» | Обёртка (Wrapper) **или** Behavior (в зависимости от файла) | по содержимому: wrapper — в `wrappers/`, предписание — в `behaviors/` |
| «Режим» / `mode/` | Behavior | переименовать в `behaviors/` |
| `dialog-settings/` | Категория применения, не сущность | разложить: Format-утилиты → `formats/`, предписания → `behaviors/` |
| `snippets/` | Историческая свалка | разобрать по §1; пустой каталог удалить |

## 8. Чек-лист при добавлении файла

- [ ] Тип определён (Role / Skill / Behavior / Format / Wrapper / Composite)?
- [ ] Файл лежит в каталоге своего типа?
- [ ] Имя оканчивается на суффикс типа (кроме Composite)?
- [ ] Если Behavior — в нём нет «Ты — …»?
- [ ] Если Skill — он stance-neutral (тест: убрать → модель берётся за задачу)?
- [ ] Если Composite — стойка одна? Версии встроенных добавок в шапке?
- [ ] Нет брата-близнеца в другом каталоге (проверить по §5)?
