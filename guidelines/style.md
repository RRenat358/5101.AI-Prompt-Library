# Гайд по стилю промптов (Style Guide)

Настоящий документ фиксирует **уникальные** правила написания и оформления
промт-артефактов, принятые в репозитории `5101.AI-Prompt-Library`.
Общеизвестные практики промт-инжиниринга здесь намеренно опущены —
сосредоточьтесь на том, что отличает именно этот проект.

Оформление тела промта — здесь. Типы сущностей и правила размещения —
[entity-taxonomy.md](entity-taxonomy.md). Формат мета-блока —
[meta-block.md](meta-block.md). Сборка композитов —
[composite-assembly.md](composite-assembly.md).


============================================================
## 1. Формат файлов и разметка

- **`.txt`** — основное расширение для промт-сущностей (Role, Skill, Behavior,
  Format, Action, Wrapper, Snippets, Composite).
- **`.GUIDE.txt`** — sidecar-гайд рядом с промтом (см. §3).
- **`.md`** — README и внешняя документация (`guidelines/`, `docs/`).
- Внутри `.txt` **можно и нужно** использовать markdown или подобное
  облегчённое форматирование для смысловых акцентов перед LLM
  (например, `**жирный текст**`, списки, цитаты).
- Для визуального структурирования, ориентированного в первую очередь на
  человека, но также считываемого LLM, применяется система **разделителей** и
  **заголовков**, описанная в отдельных гайдах (§4).


============================================================
## 2. Мета-блок

Каждый промт-артефакт начинается с мета-блока — стандартизированной шапки,
которая служит для классификации, поиска и навигации. Мета-блок помечен как
«не читать» для LLM, и модель, как правило, его пропускает. Это не 100%
гарантия, но best-practice: без метки теги и версии попадают в рабочий
контекст чаще.

Полный формат, обязательные и опциональные ключи, примеры для разных типов —
[meta-block.md](meta-block.md). Здесь не дублируем: формат один для всех,
и живёт он в одном месте.

## 3. Языковой стандарт и именование

### 3.1. Язык

- **Основной язык** промт-артефактов — **русский**. Английский допустим,
  когда это критично для точности понимания LLM (специфические термины,
  названия моделей).
- Англоязычные версии получают постфикс `.en` перед расширением:
  `промт.en.txt`.

### 3.2. Имена файлов

- **Язык имён** — русский, кроме технических терминов (`LLM`, `SKILL`).
- **Стиль** — kebab-case: пробелы заменяются на дефисы.
- **Логический разделитель** смысловых частей — точка, после неё заглавная
  буква: `Медик.Врач-и-учёный-медик.txt`, `Психолог.Критик.Коллега.txt`.
- **Расширения** — `.txt` (промты), `.md` (README), `.GUIDE.txt` (sidecar).
- **Постфикс `.en`** — для англоязычных версий.

### 3.3. Суффиксы типов

Суффиксы — **капсом**: `.ROLE`, `.SKILL`, `.BEHAVIOR`, `.FORMAT`, `.ACTION`,
`.WRAPPER`, `.SNIPPETS`, `.GUIDE`. Капс — маркер типа, а не часть имени.

**Когда суффикс нужен, а когда нет:** в папке своей сущности — без суффикса
(папка уже сказала тип). В плоском каталоге или чужой папке — с суффиксом.
Полные правила и таблица — [entity-taxonomy.md](entity-taxonomy.md), §7.

### 3.4. Имена директорий

- **Язык** — английский, lower kebab-case: `prompt-by-theme`,
  `prompt-composites`, `guidelines`.
- **Составные темы** — через тире: `it-llm`, `it-qa`. Не через точку (ломает
  иерархию в IDE и скриптах), не через подчёркивание.
- **Мета-контейнеры** — на корне, с префиксом `prompt-`: `prompt-composites/`,
  `prompt-by-theme/`, `prompt-snippets/`, `prompt-wrappers/`.

### 3.5. Сортировка и ссылки

Имена без пробелов гарантируют целостность URL и корректную работу в любых
файловых системах. Точка в имени файла — логический разделитель, не иерархия
каталогов: `Психолог.Критик.txt` остаётся одним файлом.

## 4. Визуальное оформление (обязательные ссылки)

Структура тела промта (разделители, заголовки, акценты) регламентирована
отдельными гайдами. **Изучите их перед созданием нового промта:**

- [visual-separators.md](visual-separators.md) — иерархия разделителей и
  заготовки.
- [headers.md](headers.md) — система заголовков H0–H3.

Отклонение от этих гайдов — не нарушение само по себе, но повод обосновать:
если ваш случай требует другого оформления, лучше обсудить, чем молча
игнорировать. Единообразие помогает и человеку, и агенту.


============================================================
## 5. Специфические запреты и рекомендации

- Не используйте `---` (3 дефиса) как рядовой разделитель внутри блоков —
  он зарезервирован для особых случаев (см. [visual-separators.md](visual-separators.md)).
- Избегайте смешивания в одном промте стилей оформления из разных систем
  (например, визуальные разделители + нативные markdown-заголовки `#`).
- Придерживайтесь единообразия: если в одном блоке применён определённый
  стиль заголовков, сохраняйте его во всём промте.
