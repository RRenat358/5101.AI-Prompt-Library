# Гайд по созданию промтов-ролей (стандарт репозитория)

Этот документ описывает единый форм-фактор для всех промтов, задающих роль (persona) для языковой модели. Стандарт улучшает понимание моделью, упрощает чтение, редактирование и переиспользование человеком.


============================================================
## Базовый шаблон

```
==============================
Ты — [ЯДРО РОЛИ].

[КЛЮЧЕВЫЕ СФЕРЫ]
- [Компетенция / область знаний 1]
- [Компетенция / область знаний 2]
  ...
==============================
```

### Пояснения

- **Ядро роли** — одна строка, определяющая суть персонажа. Примеры: «Ты — врач и учёный-медик», «Ты — универсальный системный администратор», «Ты — критический мыслитель-партнёр». Ядро не детализирует компетенции, только задаёт идентичность.
- **Блок компетенций** начинается с заголовка в квадратных скобках (рекомендуется `[КЛЮЧЕВЫЕ СФЕРЫ]`). Заголовок должен быть ёмким и уникальным, чтобы не пересекаться с другими инструкциями в диалоге. Альтернативные названия в зависимости от роли: `[ЗОНЫ ОТВЕТСТВЕННОСТИ]`, `[КЛЮЧЕВЫЕ НАВЫКИ]`, `[НАПРАВЛЕНИЯ]`. Придерживайтесь одного названия для единообразия репозитория; предпочтительно `[КЛЮЧЕВЫЕ СФЕРЫ]`.
- **Каждая компетенция** — отдельный пункт маркированного списка (начинается с дефиса). Пункты могут быть односложными или содержать уточняющие детали, но остаются краткими (1–2 предложения). Избегайте вложенных списков без необходимости.
- **Количество пунктов:** оптимально 3–7. При большем количестве группируйте близкие сферы.

============================================================
## Вариации и дополнительные блоки

При необходимости после основного блока компетенций можно добавить дополнительные блоки, следуя тому же стилю:
```
==============================
[ТОН И СТИЛЬ]
- 
...

==============================
[ОГРАНИЧЕНИЯ]
- 
...

==============================
```


Важно: дополнительные блоки не должны дублировать то, что модель и так делает по умолчанию. Добавляйте только критически важные ограничения, не перегружая промт.


============================================================
## Правила для авторов

1. **Не вставляйте вторую роль.** Внутри пунктов избегайте конструкций «Ты — ...». Вместо этого используйте глаголы и описания действий: «разделяй...», «указывай...», «обладаешь знаниями в...».
2. **Сохраняйте минимализм.** Не описывайте очевидные для LLM вещи (например, «отвечай на вопросы»). Каждый пункт должен нести смысловую нагрузку, углубляющую или уточняющую роль.
3. **Уточнения — только там, где модель склонна ошибаться.** Как в примере с БАДами: маркетинговое давление требует явного усиления скепсиса. В менее зашумлённых темах можно оставить общие формулировки.
4. **Используйте заголовки в квадратных скобках.** Модели обучены на структурированных документах, поэтому такое форматирование помогает выделить блоки как мета-инструкции.
5. **Совместимость с плагинами.** Если в репозитории есть обёртка `[ПОВЕДЕНЧЕСКИЙ ПЛАГИН]`, роль не должна конфликтовать с ней. Рекомендуется не вписывать в роль экстремальный скептицизм, если он уже заложен в отдельный плагин.

## Примеры (упрощённые, для демонстрации формата)


### Пример 1: повар

```
==============================
Ты — шеф-повар.

[КЛЮЧЕВЫЕ СФЕРЫ]
- Итальянская кухня и её региональные особенности.
- Китайская кухня: традиционные техники, баланс вкусов.
- Индийская кухня: использование пряностей и их сочетаний.
- Испанская кухня: тапас, паэлья, региональные ингредиенты.
==============================
```


### Пример 2: системный администратор

```
==============================
Ты — универсальный системный администратор.

[КЛЮЧЕВЫЕ СФЕРЫ]
- Клиентские и серверные Windows, Linux и другие ОС.
- Сетевое и периферийное оборудование.
- Виртуализация, контейнеризация, резервное копирование, автоматизация.
- Решение проблем: анализ логов, поиск причин ошибок, пошаговые инструкции.
==============================
```


============================================================
## Чеклист перед добавлением в репозиторий

- [ ] Роль начинается с «Ты — ...» и одной фразой задаёт идентичность.
- [ ] Присутствует блок `[КЛЮЧЕВЫЕ СФЕРЫ]` (или согласованный аналог).
- [ ] Компетенции перечислены лаконично, без избыточных правил поведения.
- [ ] Внутри пунктов нет конкурирующих «Ты — ...».
- [ ] Промт не дублирует то, что модель сделает по умолчанию.
- [ ] При необходимости указаны только критичные ограничения в отдельных блоках.


============================================================
