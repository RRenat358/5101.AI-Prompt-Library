# Гайд по созданию промтов-ролей (стандарт репозитория)

Этот документ описывает единый форм-фактор для всех промтов, задающих роль (persona) для языковой модели.  
Стандарт улучшает понимание моделью, упрощает чтение, редактирование и переиспользование человеком.  


============================================================
## Базовый шаблон

```
==============================
Ты — [ЯДРО РОЛИ].

[КОМПЕТЕНЦИИ РОЛИ]
- [Компетенция / область знаний / конкретный навык 1]
- [Компетенция / область знаний / конкретный навык 2]
  ...
==============================
```

### Пояснения

- **Ядро роли** — одна строка, определяющая суть персонажа. 
  - Примеры: «Ты — врач и учёный-медик», «Ты — универсальный системный администратор», «Ты — критический мыслитель-партнёр». 
  - Ядро не детализирует компетенции, только задаёт идентичность.
- **Блок компетенций** начинается с заголовка в квадратных скобках. 
  - Рекомендованное название — `[КОМПЕТЕНЦИИ РОЛИ]`. Оно уникально, понятно человеку и не конфликтует с другими инструкциями в диалоге. 
  - Допустимые альтернативы (если очень хочется): `[КЛЮЧЕВЫЕ КОМПЕТЕНЦИИ]`, `[ЗНАНИЯ И НАВЫКИ]`, `[КЛЮЧЕВЫЕ СФЕРЫ]`. 
  - Выберите одно и придерживайтесь его для единообразия репозитория.
- **Каждая компетенция** — отдельный пункт маркированного списка (начинается с дефиса). 
  - Пункты могут быть односложными или содержать уточняющие детали, но остаются краткими (1–2 предложения). 
  - Избегайте вложенных списков без необходимости.
- **Что можно включать**: 
  - широкие области («Китайская кухня», «Клиническая диагностика»), 
  - конкретные навыки («знаешь все бины Spring Boot», «симпатическая и парасимпатическая нервная система»), 
  - а также поведенческие или аналитические установки, если они углубляют компетенции.
- **Количество пунктов:** оптимально 3–7. При большем количестве группируйте близкие компетенции.


============================================================
## Ядро роли

`[ЯДРО РОЛИ]` -- обязательный блок. Содержит идентичность роли — кто ты. 
Формулируется максимально коротко, обычно одной фразой: «Ты — [роль]».
Дополнительно, ТОЛЬКО при необходимости, может включать главную цель или миссию роли (одно предложение).
НЕ РАЗДУВАТЬ искусственно: если роль не подразумевает явной глобальной цели, блок должен оставаться минимальным.
Примеры:
- «Ты — LLM-эксперт.» (только идентичность)
- «Ты — равный коллега. Вы вместе с собеседником исследуете вопрос.» (идентичность + миссия)


============================================================
## Вариации и дополнительные блоки

При необходимости после основного блока компетенций можно добавить другие блоки, следуя тому же стилю:

```
==============================
[ТОН И СТИЛЬ]
- 
...

==============================
[ОГРАНИЧЕНИЯ]
- 
...

==============================
```


Важно: дополнительные блоки не должны дублировать то, что модель и так делает по умолчанию.  
Добавляйте только критически важные ограничения, не перегружая промт.  


============================================================
## Правила для авторов

1. **Не вставляйте вторую роль.** Внутри пунктов избегайте конструкций «Ты — ...». 
   Вместо этого используйте глаголы и описания действий: «разделяй...», «указывай...», «обладаешь знаниями в...».
2. **Сохраняйте минимализм.** Не описывайте очевидные для LLM вещи (например, «отвечай на вопросы»). 
   Каждый пункт должен нести смысловую нагрузку, углубляющую или уточняющую роль.
3. **Уточнения — только там, где модель склонна ошибаться.** Как в примере с БАДами: 
   маркетинговое давление требует явного усиления скепсиса. В менее зашумлённых темах можно оставить общие формулировки.
4. **Используйте заголовки в квадратных скобках.** Модели обучены на структурированных документах, 
   поэтому такое форматирование помогает выделить блоки как мета-инструкции.
5. **Совместимость с плагинами.** Если в репозитории есть обёртка `[ПЛАГИН ДОПОЛНИТЕЛЬНЫХ ИНСТРУКЦИЙ]`, 
   роль не должна конфликтовать с ней. Рекомендуется не вписывать в роль экстремальный скептицизм, 
   если он уже заложен в отдельный плагин.
6. **Маркер открытости.** Последним пунктом списка компетенций всегда ставить маркер открытости. 
   - Примеры:
      - Готовность работать с любыми смежными задачами в рамках роли (не ограничивайся перечисленным).
      - Любые смежные задачи, возникающие при настройке и эксплуатации ИТ-инфраструктуры (не ограничивайся перечисленным).
      - Любые смежные медицинские и научные вопросы, вытекающие из запроса (не ограничивайся перечисленным).

## Примеры (упрощённые, для демонстрации формата)


### Пример 1: повар

```
==============================
Ты — шеф-повар.

[КОМПЕТЕНЦИИ РОЛИ]
- Итальянская кухня и её региональные особенности.
- Китайская кухня: традиционные техники, баланс вкусов.
- Индийская кухня: использование пряностей и их сочетаний.
- Испанская кухня: тапас, паэлья, региональные ингредиенты.
==============================
```


### Пример 2: системный администратор

```
==============================
Ты — универсальный системный администратор.

[КОМПЕТЕНЦИИ РОЛИ]
- Клиентские и серверные Windows, Linux и другие ОС.
- Сетевое и периферийное оборудование.
- Виртуализация, контейнеризация, резервное копирование, автоматизация.
- Решение проблем: анализ логов, поиск причин ошибок, пошаговые инструкции.
==============================
```

## Чеклист перед добавлением в репозиторий

- [ ] Роль начинается с «Ты — ...» и одной фразой задаёт идентичность.
- [ ] Присутствует блок `[КОМПЕТЕНЦИИ РОЛИ]` (или согласованный аналог).
- [ ] Компетенции перечислены лаконично, без избыточных правил поведения.
- [ ] Внутри пунктов нет конкурирующих «Ты — ...».
- [ ] Промт не дублирует то, что модель сделает по умолчанию.
- [ ] При необходимости указаны только критичные ограничения в отдельных блоках.
