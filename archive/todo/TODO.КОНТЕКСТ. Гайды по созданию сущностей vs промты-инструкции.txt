КОНТЕКСТ: Гайды по созданию сущностей vs промты-инструкции

ТЕКУЩЕЕ СОСТОЯНИЕ:
- Есть LLM.Ролевые-инструкции.BEHAVIOR.txt — промт, который одновременно
  служит инструкцией для LLM (форм-фактор роли) и документацией для человека.
  Подход «код как документация» — работает.
- Для остальных сущностей (Behavior, Skill, Format, Action, Wrapper, Snippets,
  Composite) такого файла нет. Правила размазаны по:
  - guidelines/entity-taxonomy.md (общие правила, именование, размещение)
  - guidelines/dynamic-additions.md (Behavior в диалоге)
  - guidelines/composite-assembly.md (сборка Composite)
  - prompts/<сущность>/README.md (ориентация + правила создания)
- Есть частичное дублирование: roles/README.md §«Как создать» повторяет то,
  что есть в LLM.Ролевые-инструкции.BEHAVIOR.txt. Это неизбежно, пока
  README пытается быть и гайдом, и ориентацией.

ПРОБЛЕМА:
- Два источника истины для правил создания сущностей: README и промт-инструкция.
  При правке одного — забываешь другой.
- LLM.Ролевые-инструкции.BEHAVIOR.txt устаревает (терминология: «сниппеты»,
  «плагины»; правила суффиксов; новая таксономия).
- Для новых сущностей нет аналогичного файла — правила только в гайдах.

ПРЕДЛОЖЕНИЕ (обсуждается):
1. Для каждой сущности создать behavior-промт по образцу
   LLM.Ролевые-инструкции.BEHAVIOR.txt:
   - LLM.Behavior-инструкции.BEHAVIOR.txt
   - LLM.Skill-инструкции.BEHAVIOR.txt
   - LLM.Format-инструкции.BEHAVIOR.txt
   - LLM.Action-инструкции.BEHAVIOR.txt
   - LLM.Wrapper-инструкции.BEHAVIOR.txt
   - LLM.Snippets-инструкции.BEHAVIOR.txt
   - LLM.Composite-инструкции.BEHAVIOR.txt
   Каждый файл — и промт (LLM читает как инструкцию), и документация
   (человек читает как гайд). «Код как документация».
2. Композит LLM-эксперта: LLM-эксперт + все эти behaviors.
   LLM-эксперт получает полный набор инструкций по созданию любой сущности.
3. README в папках сущностей — оставить как ориентацию (что это, как опознать,
   пример), но убрать из них §«Как создать» — он переезжает в промт-инструкцию.
   README ссылается на промт.
4. Sidecar .GUIDE.txt — опционально, на будущее. Не сейчас.
5. Обновить LLM.Ролевые-инструкции.BEHAVIOR.txt: убрать устаревшую
   терминологию, добавить правила суффиксов, привести к новой таксономии.

ЧТО РЕШИТЬ В НОВОМ ДИАЛОГЕ:
- Формат каждого behavior-промта: структура, разделы, тон.
- Как избежать дублирования между behavior-промтами (общие правила — где?).
- Судьба §«Как создать» в README: убрать полностью или оставить краткий
  чек-лист со ссылкой на промт.
- Судьба guidelines/: какие гайды остаются (общие правила), какие заменяются
  промтами (специфика сущностей).
- Обновление LLM.Ролевые-инструкции.BEHAVIOR.txt под новую таксономию.
- Композит LLM-эксперта: состав, порядок behaviors.

ТЕКУЩИЕ ФАЙЛЫ (для контекста):
- guidelines/entity-taxonomy.md — общие правила (типы, именование, размещение,
  мета-блок, правило темы, Snippets).
- guidelines/meta-block.md — формат мета-блока.
- guidelines/tagging-system.md — теги.
- guidelines/style.md — оформление, именование.
- guidelines/dynamic-additions.md — Behavior в идущем диалоге.
- guidelines/composite-assembly.md — сборка Composite.
- guidelines/stance-and-skills.md — концепция стоек и skills.
- prompts/roles/README.md — ориентация + §«Как создать» (кандидат на переезд).
- prompt-by-theme/it_llm/LLM.Ролевые-инструкции.BEHAVIOR.txt — форм-фактор
  роли (код+документация), устаревает.

ПРИНЦИП:
«Код как документация»: промт-инструкция — единственный источник истины для
правил создания сущности. README — ориентация. Guidelines — общие правила,
не специфика сущностей.
